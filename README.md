# TraceBack

你的臉被拿去打詐騙廣告或假代言時，比對出被盜用的原圖、保全證據，並整理好檢舉、通報與報案要用的資料。

它提供一般資訊與文件草稿，不是法律意見。

## 設計規範

[`DESIGN.md`](DESIGN.md) 寫下了這個網站的顏色、字型、元件、語氣與該做和不該做的事。用 AI 改介面前，先讓它讀這份檔案。

## 四個入口

| 頁面 | 給誰 | 做什麼 | 需要後端 |
|---|---|---|---|
| `index.html` | 被冒用的人 | 路徑一、路徑二：比對、存證、文件草稿 | 不需要（掃描外部網站時需要） |
| `verify.html` | 一般民眾 | 上傳可疑截圖，查是不是本人、跟本人的聲明符不符，可以交給本人確認 | 需要 |
| `kol.html` | 被冒用的人 | 登錄臉部特徵、官方帳號與「我不會做的事」，處理民眾回報 | 需要 |
| `admin.html` | 主辦團隊 | 審核登錄者、人工確認官方帳號 | 需要 |

民眾查證的四種結果、資料怎麼流、怎麼部署，見 [`backend/README.md`](backend/README.md)。

## 兩條路徑

**路徑一：我已經看到那則內容了**

1. **確認本人**：用鏡頭自拍，算出臉部特徵。
2. **加入照片**：加入自己的照片；臉與自拍不符或找不到臉的照片會被拒絕。
3. **發生了什麼事**：選擇情況、上傳可疑的圖或廣告截圖（可拖放或直接貼上）、填寫來源。
4. **比對**：四層比對，把你的照片對齊到可疑圖上，用紅色標出被改動的區域，並說明它被動了什麼手腳。
5. **留下證據**：計算 SHA-256，產生存證紀錄，可存成 PDF 或下載紀錄檔。
6. **接下來怎麼做**：依情況列出待辦清單，產生檢舉文字、報案摘要、澄清聲明等草稿。

**路徑二：幫我找找看**

在第 2 步之後多兩步，其餘相同：

- **證件驗證**：上傳身分證正面，比對證件上的臉與自拍，並勾選兩項聲明。證件影像比對完即丟棄。
- **搜尋**：系統一頁一頁看網頁上的圖片，和你的照片比對。找到的內容由你逐則確認，確認後帶入第 3 步。

涉及未滿 18 歲的不雅影像時，流程不會收取影像，只記錄文字資訊並引導通報。路徑二不會主動搜尋不雅影像。

## 搜尋怎麼運作

別人的圖片抓回瀏覽器後在本機比對，使用者的照片不會送出去。

**依權重決定先看哪一頁**（`js/search.js`）

- 每個連結依文字特徵算分：是否提到投資獲利、是否催促行動、是否提到名人老師、是否標示為贊助、離起點多遠。
- 每次從待看清單挑分數最高的連結。
- 起始權重是人工設定的。使用者確認或否定搜尋結果後，系統以邏輯迴歸調整權重，存在瀏覽器的 localStorage。

**兩階段比對**

- 先用感知雜湊、特徵向量與人臉粗篩。
- 通過的才做特徵點比對與改動區域標示。

**兩種來源**

| 來源 | 說明 |
|---|---|
| 模擬網路 | 用使用者自己的照片在瀏覽器裡做出五則模擬假廣告（加橫幅、裁切翻轉、放進商品版面、換背景、原圖轉貼），混進 19 個模擬網頁。不連到任何真實網站。每張模擬圖都有「示範用模擬內容」標記。 |
| 指定網頁 | 讀取網址的 HTML，取出連結與圖片，只在同一個網站內往下看。外部網站經後端的轉送服務讀取；需要登入的頁面讀不到。 |

示範搜尋結束時會顯示對照：依權重看 11 頁找到幾則，以及不排序、照連結順序看 11 頁會遇到幾則。

## 測試站

`testsite/` 是一組虛構的網頁，給「幫我找找看」的掃描示範用。搜尋頁預設就是掃描測試站，掃描本站頁面不需要證件驗證。

其中三頁要放用成員照片做的模擬廣告圖，掃描才找得到東西：

- `testsite/img/ad-teacher.jpg`
- `testsite/img/ad-line.jpg`
- `testsite/img/ad-health.jpg`

做法：

1. 打開 `make-testsite.html`（製作測試站廣告），放入 1 到 3 張同一位成員的照片，勾選同意後按「做出三張圖」，再按「下載三張圖」。圖上都會標示「示範用模擬內容」。
2. 把三張圖放進 `testsite/img/`，檔名不要改，推上 GitHub。
3. 展示時，用同一位成員的照片走「幫我找找看」，就會從測試站找到這三則。存證紀錄會把來源標成「內建測試站（虛構網頁，示範用）」。

2026/11/14 用範例照片測過：掃描測試站 8 頁、比對 9 張圖，三則都找到並認出改動類型。測試用的圖沒有放進儲存庫。

## 掃描外部網站

瀏覽器不能直接讀取別的網站，所以外部網頁與圖片經後端的轉送服務（`/api/proxy`）讀取，已經上線。轉送服務只轉送公開的網頁與圖片、5 MB 以內，擋內部網路位址，不保存內容。需要登入才看得到的內容（Facebook、Instagram、Threads 的大部分頁面、LINE 群組）讀不到。圖片會讀 `src`、`data-src`、`data-original`、`srcset` 與 `og:image`。

## 四層比對

| 層 | 方法 | 實作 |
|---|---|---|
| 1 | 感知雜湊 | 自行實作的 64 位元 pHash |
| 2 | 影像特徵向量 | Transformers.js 執行 DINOv2-small |
| 3 | 局部特徵點加幾何驗證 | OpenCV.js 的 ORB、RANSAC 單應性矩陣 |
| 4 | 人臉相似度 | face-api 的 128 維臉部特徵 |

其他層顯示可能相關、但特徵點對不上時，會把可疑圖左右翻轉後再比一次。

判斷門檻集中在 `js/matching.js` 的 `THRESHOLDS`，目前都是暫定值，要用比對實驗的結果校正。

## 改動類型判斷

找到來源照片後，系統把你的照片對齊到可疑圖上，量出下列數值，再依規則說明「它被動了什麼手腳」。一張圖可以同時有好幾種。

| 量什麼 | 判斷成 |
|---|---|
| 你的照片占可疑圖的比例偏低 | 放進別的版面 |
| 你的照片只有一部分出現在可疑圖裡 | 裁切 |
| 翻轉後才對得上 | 左右翻轉 |
| 臉部區域的改動比例高，那裡偵測到另一張臉 | 臉被換成另一張臉 |
| 臉部區域的改動比例高，那裡偵測不到臉 | 臉被遮住或改到認不出來 |
| 臉部區域的改動比例高，那裡仍然認得出是本人 | 臉部被修改 |
| 臉以外的改動比例高，或照片外圍一整圈都被改掉 | 背景或身體被換掉 |
| 臉以外有一部分被改 | 加上文字或貼圖 |
| 以上都沒有 | 原圖直接使用 |
| 只有臉像，其他都對不上 | 只有臉像你（無法分辨是換臉、用了別張照片，還是整張重新生成） |

這是規則，不是模型；數值是量出來的，不受壓縮或截圖影響的程度比「疑似 AI 生成」的猜測高。門檻在 `js/matching.js` 的 `THRESHOLDS`（`edit` 開頭的幾項），都是暫定值。

2026/11/13 用程式做的 11 種改法試跑，類型都判斷正確：五則模擬廣告，加上換上別人的臉、蓋住臉、調整臉部色調、把臉貼到別人的照片上、小貼圖、重新壓縮。這些都是簡單的剪貼，不是真正用 AI 工具做的修改；AI 換臉或重繪時，臉不是原圖的像素，判斷會落在哪一類還不知道，要用實驗頁驗證。

實驗頁的「改動類型的判斷」表會列出每種處理方式的改造圖各被判成什麼，拿它和實際做的處理對照。

## 換臉與 AI 生成的線索

比對結果頁與民眾查證頁都有「其他線索」，四種都是輔助訊號，不單獨下結論。

| 線索 | 做法 | 限制 |
|---|---|---|
| 檔案來源標記（`js/provenance.js`） | 讀 C2PA 內容憑證、IPTC 的 DigitalSourceType、Stable Diffusion 與 ComfyUI 寫進 PNG 的參數，看有沒有標示 AI 生成 | 不驗證簽章，標記可以偽造；截圖與上傳社群平台通常會洗掉標記 |
| 換臉檢查（`js/faceparts.js`） | 用 68 個臉部特徵點把臉分成「五官」與「臉型」兩區，各算一次臉部特徵和本人比較。五官像本人、臉型不像，就是把本人的臉換到別人身上 | 門檻是用 face-api 範例照片粗估的；外臉的鑑別力弱；沒用真正的換臉工具測過 |
| 圖上的詐騙話術（`js/scamtext.js`） | 使用者按下按鈕才用 Tesseract.js 讀出圖上的繁中與英文文字（語言檔約 5 MB），再用規則找七類話術：保證獲利、報明牌或帶單、要你加入群組或私訊、匯款或虛擬貨幣、免費領取、催你馬上行動、名人或老師背書，並抓出 LINE ID、t.me、wa.me 等聯絡方式。前四類單獨出現就算數，後三類一般廣告也常見，要和其他項一起出現才算。規則同時認繁體與簡體寫法 | 字太小、太糊或是藝術字時讀不出來，也會認錯字；規則只認得列出的說法，換個說法就漏掉；還沒有用真的詐騙廣告和正常廣告測過誤報率 |
| 疑似 AI 生成分數（`js/aidetect.js`） | 使用者按下按鈕才下載偵測模型（約 87 MB）並計算 | 廣告常見的縮圖、壓縮、加字會讓它漏掉大部分 AI 圖，分數低不代表是真的 |

民眾查證時，換臉檢查在伺服器上做：登錄時同時保存五官與臉型的特徵，查證時完整的臉對不上、但五官很像某位登錄者且臉型不像，也會認出是誰並標示可能換臉。

2026/11/24 用程式畫的一張假廣告測過文字辨識：讀出全部四行字，只把「飆」認成另一個字，命中六類話術與 LINE ID，判為「很像投資詐騙廣告」，含第一次下載約 10 秒。規則另外用幾段文字試過：繁中、簡中、英文的詐騙話術都判為很像詐騙；購物網站的「限時優惠、立即購買」與財經新聞的「分析師表示」沒有被判為詐騙。

命中的話術會記進存證紀錄與文件草稿的「其他線索」。目前只用規則，沒有接大型語言模型；要接的話，只把讀出的文字送給後端判斷，圖片仍不離開瀏覽器。

2026/11/13 的粗估（不是正式實驗）：

- 不同人的五官距離最小 0.43，同一張照片經縮放、壓縮、旋轉後最大 0.40；臉型距離不同人中位數 0.32，同一人最大 0.24。
- 用剪貼做的 11 組粗糙換臉，在目前門檻（五官 0.40 或 0.45、臉型 0.28）只抓到少數幾組。拿去示範的那組（範例照片 3 的五官換到照片 6 上）在兩個頁面都被標出來，同一人的真照片沒有誤報。
- 讀得到 C2PA 官方測試檔的憑證與「由演算法產生」的標示，也讀得到自製的 IPTC 標示。

## 比對實驗頁

`experiment.html` 用來產出企劃書要用的數字：被改過的照片還認不認得出來源。

1. 放入本人的照片（1 到 10 張）。系統會自動做出六種常見改法：加廣告橫幅、裁切翻轉加濾鏡、放進商品版面、縮小轉貼加圖說、換背景、縮小加重度壓縮。
2. 選填別人的照片：測會不會誤認別人，並自動做出「把本人的五官貼到別人臉上」的換臉圖，測換臉檢查。
3. 選填自己用 AI 工具做的改造圖，每張選它從哪張原圖改來。舊的命名方式（`a01__AI換背景.jpg`）會自動帶入。
4. 可勾選同時算疑似 AI 生成分數。

結果頁先給數字與結論（認出幾張、誤認幾張、換臉標出幾張、真照片被誤判為 AI 幾張），再列每種改法的結果與沒認出來的圖。各層數值收在可展開的區塊，給調門檻用。可以複製結果貼到企劃書，或下載 CSV。

自動改法與自動換臉都是剪貼，不是真正的 AI 工具；要證明對 AI 改造的效果，一定要放第 3 組。

## 疑似 AI 生成分數（試驗中）

實驗頁可以勾選「同時計算疑似 AI 生成分數」。它用 Community Forensics 的偵測模型（`js/aidetect.js`，約 87 MB）對每張圖打 0 到 1 的分數，並依類別列出分布。這是沒有原圖可對照時的猜測，只能當輔助訊號。比對結果頁與民眾查證頁可以按按鈕選用。

2026/11/13 用公開資料集各取約 20 張做的小規模試跑（不是正式實驗）：

| 圖片 | 未處理 | 縮到 560 像素並以品質 60 壓縮 | 再加上廣告橫幅 |
|---|---|---|---|
| 真實人像（FFHQ、CelebA-HQ，共 40 張）被判為疑似 | 0 張 | 1 張 | 0 張 |
| Flux 生成的人像（20 張）被判為疑似 | 12 張 | 4 張 | 0 張 |
| Midjourney v6 生成的圖（19 張）被判為疑似 | 4 張 | 0 張 | 0 張 |

判為疑似的門檻是 0.5。從這次試跑看到的：

- 真實照片幾乎不會被誤報，所以分數高時有參考價值。
- 分數低不代表不是 AI 生成：未處理的生成圖也漏掉不少，重度壓縮或加上橫幅後幾乎偵測不到。
- 只做輕度壓縮或只縮小，影響不大；兩者一起做才會大幅下降。
- 沒有測到「真實照片被 AI 局部修改」的情況，這要用成員自己的照片做。

另外兩個較小的候選模型：一個對真實照片接近亂猜，一個的訓練資料是 32 像素的小圖，沒有採用。

## 隱私

- 路徑一、路徑二的照片、自拍、證件與證據都只在瀏覽器裡處理，沒有任何上傳。
- 本人登錄與民眾查證會用到後端，但只送出臉部特徵數值；民眾同意回報時才上傳縮小後的截圖。細節見 `backend/README.md`。
- 文字辨識也在瀏覽器裡執行，讀出的文字不會送出去。
- 函式庫與模型檔會從 jsDelivr 與 Hugging Face 下載，第一次使用需要等待。
- 資料只存在記憶體，關閉或重新整理頁面就消失。唯一寫入瀏覽器儲存空間的是搜尋權重，不含任何影像或個人資料。

## 尚未完成

- 後端已部署到 https://traceback-api.traceback-nextwave.workers.dev 。
- 自建索引與排程爬取還沒做；外部網站只能在使用者指定網址時掃描。
- 本人登錄沒有防偽與證件驗證，用人工審核代替。
- 證件驗證：只比對證件上的臉，不讀取證件文字，也無法判斷證件真偽。
- 活體檢測：目前只擷取鏡頭的即時畫面，沒有防偽；上傳自拍照僅供展示。
- 第三方時間戳與本機加密保存：目前時間取自裝置時鐘，資料不落地保存。
- 影片：目前只接受圖片，影片請先截圖。
- 法律文字（`js/templates.js`）尚未經法律成員審核。
- 搜尋權重的學習只用單次搜尋的少量資料，僅示範機制，沒有驗證效果。

## 在自己的電腦上執行

需要用網頁伺服器開啟，直接點兩下 `index.html` 無法載入模組。要測民眾查證與本人登錄，先依 `backend/README.md` 啟動本機後端。

```bash
python3 -m http.server 8765
```

然後開啟 `http://localhost:8765`。鏡頭功能需要 localhost 或 HTTPS。

## 部署到 GitHub Pages

1. 把這個資料夾的內容推到 GitHub 儲存庫。
2. 到儲存庫的 Settings，選 Pages，Source 選 `Deploy from a branch`，分支選 `main`、資料夾選 `/ (root)`。
3. 等一兩分鐘後，網址會顯示在同一頁。

## 放進儲存庫前請確認

- 不要提交真人照片、身分證件或任何不雅內容。
- 展示用的範例請用成員本人同意公開的照片，自製模擬廣告。
- 不要提交任何金鑰。
