# TraceBack

你的臉被拿去打詐騙廣告或假代言時，比對出被盜用的原圖、保全證據，並整理好檢舉、通報與報案要用的資料。

它提供一般資訊與文件草稿，不是法律意見。

## 兩條路徑

**路徑一：我已經看到那則內容了**

1. **確認本人**：用鏡頭自拍，算出臉部特徵。
2. **加入照片**：加入自己的照片；臉與自拍不符或找不到臉的照片會被拒絕。
3. **發生了什麼事**：選擇情況、上傳可疑的圖或廣告截圖（可拖放或直接貼上）、填寫來源。
4. **比對**：四層比對，把你的照片對齊到可疑圖上，用紅色標出被改動的區域，並說明它被動了什麼手腳。
5. **留下證據**：計算 SHA-256，產生存證紀錄，可存成 PDF 或下載紀錄檔。
6. **接下來怎麼做**：依情況列出待辦清單，產生檢舉文字、報案摘要、澄清聲明等草稿。

**路徑二：幫我找找看**

在第 2 步之後多兩步，其餘相同：

- **證件驗證**：上傳身分證正面，比對證件上的臉與自拍，並勾選兩項聲明。證件影像比對完即丟棄。
- **搜尋**：系統一頁一頁看網頁上的圖片，和你的照片比對。找到的內容由你逐則確認，確認後帶入第 3 步。

涉及未滿 18 歲的不雅影像時，流程不會收取影像，只記錄文字資訊並引導通報。路徑二不會主動搜尋不雅影像。

## 搜尋怎麼運作

別人的圖片抓回瀏覽器後在本機比對，使用者的照片不會送出去。

**依權重決定先看哪一頁**（`js/search.js`）

- 每個連結依文字特徵算分：是否提到投資獲利、是否催促行動、是否提到名人老師、是否標示為贊助、離起點多遠。
- 每次從待看清單挑分數最高的連結。
- 起始權重是人工設定的。使用者確認或否定搜尋結果後，系統以邏輯迴歸調整權重，存在瀏覽器的 localStorage。

**兩階段比對**

- 先用感知雜湊、特徵向量與人臉粗篩。
- 通過的才做特徵點比對與改動區域標示。

**兩種來源**

| 來源 | 說明 |
|---|---|
| 模擬網路 | 用使用者自己的照片在瀏覽器裡做出五則模擬假廣告（加橫幅、裁切翻轉、放進商品版面、換背景、原圖轉貼），混進 19 個模擬網頁。不連到任何真實網站。每張模擬圖都有「示範用模擬內容」標記。 |
| 指定網頁 | 讀取網址的 HTML，取出連結與圖片，只在同一個網站內往下看。目前只能掃描本站頁面，例如 `testsite/`。 |

示範搜尋結束時會顯示對照：依權重看 11 頁找到幾則，以及不排序、照連結順序看 11 頁會遇到幾則。

## 測試站

`testsite/` 是一組虛構的網頁，給「掃描指定網頁」示範用。其中三頁預留了模擬廣告圖的位置：

- `testsite/img/ad-teacher.jpg`
- `testsite/img/ad-line.jpg`
- `testsite/img/ad-health.jpg`

這三個檔案沒有放進儲存庫。要示範時，請用成員本人同意公開的照片自製模擬廣告後放入。做法之一：在示範搜尋的結果上按右鍵另存圖片。

## 掃描外部網站

瀏覽器不能直接讀取別的網站，需要一層轉送服務。`proxy/worker.js` 是 Cloudflare Worker 的程式，**尚未部署，也尚未測試**。部署後把位址填進 `js/config.js` 的 `PROXY_URL`。

## 四層比對

| 層 | 方法 | 實作 |
|---|---|---|
| 1 | 感知雜湊 | 自行實作的 64 位元 pHash |
| 2 | 影像特徵向量 | Transformers.js 執行 DINOv2-small |
| 3 | 局部特徵點加幾何驗證 | OpenCV.js 的 ORB、RANSAC 單應性矩陣 |
| 4 | 人臉相似度 | face-api 的 128 維臉部特徵 |

其他層顯示可能相關、但特徵點對不上時，會把可疑圖左右翻轉後再比一次。

判斷門檻集中在 `js/matching.js` 的 `THRESHOLDS`，目前都是暫定值，要用比對實驗的結果校正。

## 改動類型判斷

找到來源照片後，系統把你的照片對齊到可疑圖上，量出下列數值，再依規則說明「它被動了什麼手腳」。一張圖可以同時有好幾種。

| 量什麼 | 判斷成 |
|---|---|
| 你的照片占可疑圖的比例偏低 | 放進別的版面 |
| 你的照片只有一部分出現在可疑圖裡 | 裁切 |
| 翻轉後才對得上 | 左右翻轉 |
| 臉部區域的改動比例高，那裡偵測到另一張臉 | 臉被換成另一張臉 |
| 臉部區域的改動比例高，那裡偵測不到臉 | 臉被遮住或改到認不出來 |
| 臉部區域的改動比例高，那裡仍然認得出是本人 | 臉部被修改 |
| 臉以外的改動比例高，或照片外圍一整圈都被改掉 | 背景或身體被換掉 |
| 臉以外有一部分被改 | 加上文字或貼圖 |
| 以上都沒有 | 原圖直接使用 |
| 只有臉像，其他都對不上 | 只有臉像你（無法分辨是換臉、用了別張照片，還是整張重新生成） |

這是規則，不是模型；數值是量出來的，不受壓縮或截圖影響的程度比「疑似 AI 生成」的猜測高。門檻在 `js/matching.js` 的 `THRESHOLDS`（`edit` 開頭的幾項），都是暫定值。

2026/11/13 用程式做的 11 種改法試跑，類型都判斷正確：五則模擬廣告，加上換上別人的臉、蓋住臉、調整臉部色調、把臉貼到別人的照片上、小貼圖、重新壓縮。這些都是簡單的剪貼，不是真正用 AI 工具做的修改；AI 換臉或重繪時，臉不是原圖的像素，判斷會落在哪一類還不知道，要用實驗頁驗證。

實驗頁的「改動類型的判斷」表會列出每種處理方式的改造圖各被判成什麼，拿它和實際做的處理對照。

## 比對實驗頁

`experiment.html` 用來批次測試四層比對，產出企劃書要用的認回率與誤判率。

準備三組圖片：

- **原圖**：本人同意使用的照片，例如 `a01.jpg`。
- **改造圖**：檔名用「原圖主檔名、兩個底線、處理方式」，例如 `a01__加字.jpg`、`a01__AI換背景.png`。
- **對照圖**：不是由任何原圖改來的照片，例如同一人的其他照片，用來測誤判。

頁面會把每張測試圖和每張原圖都比一次，顯示各層的認回率、誤判率、數值分布與沒被認回的清單，並可下載全部配對的原始數值（CSV）。請不要使用任何不雅影像。

## 疑似 AI 生成分數（試驗中）

實驗頁可以勾選「同時計算疑似 AI 生成分數」。它用 Community Forensics 的偵測模型（`js/aidetect.js`，約 87 MB）對每張圖打 0 到 1 的分數，並依類別列出分布。這是沒有原圖可對照時的猜測，只能當輔助訊號。主流程目前沒有使用。

2026/11/13 用公開資料集各取約 20 張做的小規模試跑（不是正式實驗）：

| 圖片 | 未處理 | 縮到 560 像素並以品質 60 壓縮 | 再加上廣告橫幅 |
|---|---|---|---|
| 真實人像（FFHQ、CelebA-HQ，共 40 張）被判為疑似 | 0 張 | 1 張 | 0 張 |
| Flux 生成的人像（20 張）被判為疑似 | 12 張 | 4 張 | 0 張 |
| Midjourney v6 生成的圖（19 張）被判為疑似 | 4 張 | 0 張 | 0 張 |

判為疑似的門檻是 0.5。從這次試跑看到的：

- 真實照片幾乎不會被誤報，所以分數高時有參考價值。
- 分數低不代表不是 AI 生成：未處理的生成圖也漏掉不少，重度壓縮或加上橫幅後幾乎偵測不到。
- 只做輕度壓縮或只縮小，影響不大；兩者一起做才會大幅下降。
- 沒有測到「真實照片被 AI 局部修改」的情況，這要用成員自己的照片做。

另外兩個較小的候選模型：一個對真實照片接近亂猜，一個的訓練資料是 32 像素的小圖，沒有採用。

## 隱私

- 照片、自拍、證件與證據都只在瀏覽器裡處理，沒有任何上傳。這個網站沒有後端。
- 函式庫與模型檔會從 jsDelivr 與 Hugging Face 下載，第一次使用需要等待。
- 資料只存在記憶體，關閉或重新整理頁面就消失。唯一寫入瀏覽器儲存空間的是搜尋權重，不含任何影像或個人資料。

## 尚未完成

- 掃描外部網站：轉送服務未部署。自建索引與排程爬取也還沒做。
- 證件驗證：只比對證件上的臉，不讀取證件文字，也無法判斷證件真偽。
- 活體檢測：目前只擷取鏡頭的即時畫面，沒有防偽；上傳自拍照僅供展示。
- 第三方時間戳與本機加密保存：目前時間取自裝置時鐘，資料不落地保存。
- 影片：目前只接受圖片，影片請先截圖。
- 法律文字（`js/templates.js`）尚未經法律成員審核。
- 搜尋權重的學習只用單次搜尋的少量資料，僅示範機制，沒有驗證效果。

## 在自己的電腦上執行

需要用網頁伺服器開啟，直接點兩下 `index.html` 無法載入模組。

```bash
python3 -m http.server 8765
```

然後開啟 `http://localhost:8765`。鏡頭功能需要 localhost 或 HTTPS。

## 部署到 GitHub Pages

1. 把這個資料夾的內容推到 GitHub 儲存庫。
2. 到儲存庫的 Settings，選 Pages，Source 選 `Deploy from a branch`，分支選 `main`、資料夾選 `/ (root)`。
3. 等一兩分鐘後，網址會顯示在同一頁。

## 放進儲存庫前請確認

- 不要提交真人照片、身分證件或任何不雅內容。
- 展示用的範例請用成員本人同意公開的照片，自製模擬廣告。
- 不要提交任何金鑰。
