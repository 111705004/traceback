# TraceBack

你的臉被拿去打詐騙廣告或假代言時，比對出被盜用的原圖、保全證據，並整理好檢舉、通報與報案要用的資料。

它提供一般資訊與文件草稿，不是法律意見。

## 這一版做了什麼

路徑一「我已經看到那則內容」的完整流程：

1. **確認本人**：用鏡頭自拍，算出臉部特徵。
2. **參考照片**：加入自己的照片；臉與自拍不符或找不到臉的照片會被拒絕。
3. **可疑內容**：選擇情況、填寫來源資訊、上傳可疑的圖或廣告截圖。
4. **比對**：四層比對，並把參考照對齊到可疑圖上，用紅色標出被改動的區域。
5. **存證**：計算 SHA-256，產生存證紀錄，可列印成 PDF 或下載紀錄檔。
6. **行動**：依情況顯示可以走的路，產生檢舉文字、報案摘要、澄清聲明等草稿。

涉及未滿 18 歲的不雅影像時，流程不會收取影像，只記錄文字資訊並引導通報。

## 四層比對

| 層 | 方法 | 實作 |
|---|---|---|
| 1 | 感知雜湊 | 自行實作的 64 位元 pHash |
| 2 | 影像特徵向量 | Transformers.js 執行 DINOv2-small |
| 3 | 局部特徵點加幾何驗證 | OpenCV.js 的 ORB、RANSAC 單應性矩陣 |
| 4 | 人臉相似度 | face-api 的 128 維臉部特徵 |

判斷門檻集中在 `js/matching.js` 的 `THRESHOLDS`，目前都是暫定值，要用比對實驗的結果校正。

## 比對實驗頁

`experiment.html` 用來批次測試四層比對，產出企劃書要用的認回率與誤判率。

準備三組圖片：

- **原圖**：本人同意使用的照片，例如 `a01.jpg`。
- **改造圖**：檔名用「原圖主檔名、兩個底線、處理方式」，例如 `a01__加字.jpg`、`a01__AI換背景.png`。
- **對照圖**：不是由任何原圖改來的照片，例如同一人的其他照片，用來測誤判。

頁面會把每張測試圖和每張原圖都比一次，顯示：

- 各層與綜合判斷的認回率、對照圖誤判率、配錯原圖的比例
- 依處理方式分開的認回率
- 「應該相符」與「不該相符」兩組的數值分布，用來決定門檻
- 沒被認回的改造圖清單

可以下載全部配對的原始數值（CSV），或複製摘要表格貼到文件。請不要使用任何不雅影像。

速度參考：每張圖約需數秒；20 張原圖配 80 張測試圖大約要幾分鐘。

## 隱私

- 照片、自拍與證據都只在瀏覽器裡處理，沒有任何上傳。這個網站沒有後端。
- 函式庫與模型檔會從 jsDelivr 與 Hugging Face 下載，第一次使用需要等待。
- 資料只存在記憶體，關閉或重新整理頁面就消失。

## 在自己的電腦上執行

需要用網頁伺服器開啟，直接點兩下 `index.html` 無法載入模組。

```bash
python3 -m http.server 8765
```

然後開啟 `http://localhost:8765`。鏡頭功能需要 localhost 或 HTTPS。

## 部署到 GitHub Pages

1. 把這個資料夾的內容推到 GitHub 儲存庫。
2. 到儲存庫的 Settings，選 Pages，Source 選 `Deploy from a branch`，分支選 `main`、資料夾選 `/ (root)`。
3. 等一兩分鐘後，網址會顯示在同一頁。

## 放進儲存庫前請確認

- 不要提交真人照片、身分證件或任何不雅內容。
- 展示用的範例請用成員本人同意公開的照片，自製模擬廣告。
- 不要提交任何金鑰。
